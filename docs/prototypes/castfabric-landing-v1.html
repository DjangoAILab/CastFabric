跑在 NAS / Home Server 上的本地音频投放服务

不挑协议，
投了就播。

接收手机和电脑投来的 DLNA、AirPlay 与妙播，再送到支持标准 DLNA 的音响；没有原生 DLNA 的旧小米音箱，可按需启用 MiNA 兼容输出。

RECEIVER INPUTS · 已实现DLNA · AirPlay · MiPlay

手机和电脑继续使用原有投放入口。

CORE OUTPUT · 已实现Standard DLNA

驱动实现 AVTransport 与 RenderingControl 的设备。

OPTIONAL OUTPUT · 已实现Xiaomi MiNA

旧 MiAir 兼容路径；默认关闭并需要小米账号。

EXTENSION BOUNDARY · 未承诺协议PlaybackTarget

为后续输出适配器留出接口，不把规划写成支持。

一眼看懂全屋声路

最多展开三条活跃路径，其余聚合，不让音响数量破坏首页。

每台音响独立管理

启停只影响当前音响的 Receiver Suite，不存在全局默认输出。

成功必须真的拉到声音

实体音响没有拉取 HTTP 音频时，不把控制命令成功冒充播放成功。

HOW IT WORKS · 三个实际步骤

发现音响，发布入口，
确认实体设备拉到声音。

01

发现局域网音响

扫描标准 UPnP/DLNA MediaRenderer，不要求先登录小米或其他厂商账号。

SSDP → device description → services
02

发布独立接收入口

每台已启用音响获得自己的 DLNA、AirPlay 和妙播名称，多个房间可以同时存在。

Receiver Suite × output speaker
03

把声音送到实体输出

CastFabric 不止发送控制命令，还确认实体 DMR 真正打开并拉取音频流。

SOAP Play → HTTP GET → verified output

RUN FROM GHCR · LINUX HOME SERVER

一条命令启动
CastFabric。

镜像公开托管在 GitHub Container Registry，提供 amd64 与 arm64。使用 host network，让 SSDP 和 mDNS 正常访问局域网；配置保存在宿主机目录。

两条声路，两种延迟

原生 DLNA 直投在当前测试音箱通常低于 1 秒；AirPlay 与妙播经过实时 PCM / DLNA 桥接约有 4 秒延迟，不适合需要音画同步的视频。不同音箱的缓冲策略不同，实际结果以设备为准。

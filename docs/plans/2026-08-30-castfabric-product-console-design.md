# CastFabric 产品与控制台设计

## 文档状态

产品模型有效；视觉原型 v1 已否决，v2 的图形方向有效但单页信息架构未通过评审，
v3 仅保留三页面信息架构参考。v4 已按“逐页确认”原则完成首页主题稿，等待首页视觉
确认后再设计音响页。本文只定义产品，不授权修改运行代码、部署或协议实现。

## 一句话定位

**CastFabric 是面向局域网音响的开源多协议接收与路由层。**

面对普通用户的表达是：**不挑协议，投了就播。**

它不假装自己是播放器，也不要求用户理解转码链路。用户只需知道：家里的音响是否
可投、当前是谁在播放、某次投放为什么没有成功。

## 核心产品模型

```text
局域网
  ├─ 客厅音箱（启用）
  │    └─ Receiver Suite：DLNA / AirPlay / MiPlay
  ├─ 卧室音箱（启用）
  │    └─ Receiver Suite：DLNA / AirPlay / MiPlay
  └─ 书房音箱（停用）
       └─ 不发布 CastFabric 接收入口
```

这里没有“唯一选中的音响”。每台音响独立启停、独立暴露接收入口、独立记录会话；
不同音响可以同时播放，同一音响上的不同协议则遵循会话接管规则。

## 信息架构

### 1. 总览

回答三个问题：

1. CastFabric 整体是否正常？
2. 哪些音响现在可投、正在播放或需要处理？
3. 最近发生了什么？

首屏不放表单。唯一品牌 slogan 为“不挑协议，投了就播”，不再增加第二句巨型主标题。
总览是固定单屏的实时声场，只展开最多三条活跃会话和一个异常摘要；空闲音响只显示
聚合数量。完整音响状态和活动记录分别进入独立页面，不再出现在总览下方。

### 2. 音响

管理输出端。每张音响卡包含：名称、位置/地址、实体 DLNA 可达性、CastFabric 启停、
Receiver Suite 三协议状态、当前会话和最后活跃时间。启停是单台音响级操作，不使用
单选框或“设为当前输出”。

### 3. 活动

提供可诊断的事件流。每条记录包含时间、音响、协议、发送源、动作、结果和简短原因；
支持按音响、协议、结果过滤。默认展示面向用户的摘要，技术细节按条展开。

### 4. 连接配置

作为独立弹窗/抽屉存在，不挤在总览中。包含：

- 局域网发现：扫描状态、网卡、最近扫描时间；
- 接收入口：默认名称前缀、按音响别名、协议入口健康；
- 网络与端口：仅在冲突或高级使用时展开；
- 扩展：小米账号等厂商能力，默认关闭并明确为非核心依赖；
- 系统：语言、日志级别、版本、更新与导出诊断。

## 首页状态规则

总体状态不是所有服务状态的简单平均：

- **正常**：至少一台音响启用，且所有已启用音响的实体输出可达；
- **需留意**：部分音响离线或某个协议入口降级，但仍有可用投放路径；
- **不可用**：没有任何已启用且可达的音响；
- **正在发现**：首次扫描尚未完成，使用明确的临时状态，不误报故障。

音响状态分为“正在播放”“等待投放”“需留意”“已停用”。首页不展示原始端口号、
token 或配置字段。

## 关键交互

- 点击音响行进入该音响详情，不改变其他音响状态。
- 在音响详情中启停 Receiver Suite；危险影响必须在控件旁直接说明。
- 点击活跃会话可查看输入协议、媒体格式、开始时间、控制事件和输出健康。
- “重新发现”属于连接配置，扫描期间保留现有音响，不让列表闪空。
- 中英文切换即时生效；协议名、品牌名和设备原始名称不翻译。

## 视觉方向：Warm Signal Route

界面采用温暖、明亮、克制的编辑式系统：暖白画布、深墨正文、珊瑚活跃信号、苔绿健康
状态。首页只保留一条有方向的当前声路，而不是随音响数量增长的户型瀑布或装饰性拓扑。
声路表达发送端、接收协议、CastFabric 和实际播放目标；完整设备集合下沉到音响页。
不存在会话时不绘制虚假流动路径。

动效遵守因果关系：新会话从协议标签流向对应音响；播放时只有当前音响轨迹缓慢流动；
暂停时冻结；故障时不抖动，只改变状态与说明。`prefers-reduced-motion` 下关闭循环动画。

[单屏总览与三页面导航研究](../design/research/2026-08-30-castfabric-single-screen-navigation-study.md)。

## 文案基线

- 品牌语句：`不挑协议，投了就播`
- 总览正常：`全屋声路正常`
- 空闲说明：`音响已就绪，打开常用 App 即可投放`
- 部分异常：`还有音响可用，1 台需要处理`
- 停用说明：`停用后，这台音响的 CastFabric 接收入口将从投放列表中消失`
- 厂商扩展：`可选扩展，不影响标准 DLNA 音响`

英文对应文案以自然表达为准，不逐字翻译：

- `Cast freely. It just plays.`
- `Every active route is healthy.`
- `Your speakers are ready for casting.`

## 响应式与无障碍

- 桌面端使用状态总览 + 音响矩阵；移动端改为单列，但不隐藏音响和活动关键字段。
- 所有可点击区域至少 44×44 px；仅图标按钮必须有可见提示或 `aria-label`。
- 状态不能只靠颜色表达；正文与背景至少满足 WCAG AA 对比度。
- 键盘可以完成导航、打开/关闭连接配置、切换筛选和进入音响详情。

## 原型验收范围

完整控制台原型最终至少覆盖：

1. 三台音响并存，其中两台启用、一台停用；
2. 一台正在通过 MiPlay 播放，另一台等待投放；
3. 单台音响的启停和协议健康信息；
4. 最近活动包含音响名称；
5. 连接配置弹窗及中英文切换；
6. 桌面与移动布局；
7. 空闲、部分异常和发现中三种替代状态。

当前逐页验收只覆盖 v4 首页：桌面单屏、移动端、四种会话状态、三档来源信息降级和
完整中英文切换。音响、活动与连接配置在首页主题确认后分别设计，不以 v3 视觉稿作为
默认实现依据。

## 明确不在本轮做的事

- 不修改生产 Web UI 或后端 API；
- 不设计音乐播放器、播放队列或媒体库；
- 不开放未完成的配对码功能；
- 不把小米账号登录放回主流程；
- 不开始端口分配、服务编排或配置迁移实现。

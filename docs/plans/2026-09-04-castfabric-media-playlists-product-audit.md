# CastFabric 媒体资源与 Playlist 产品任务审计

状态：产品功能边界与关键路径线框图已于 2026-09-05 获批；授权生产实现
日期：2026-09-04

## 1. 审计结论

CastFabric 不能把 SQLite 中的六类对象直接变成六种 UI。用户真正面对的只有三类日常对象：

1. **音响**：声音最终去哪里；
2. **播放列表**：想按什么顺序播放哪些内容；
3. **音频资源**：可以被复用、搜索和放入 Playlist 的单段内容。

当前播放、续播位置、播放记录和活动事件都是这些对象的状态或投影，不应和它们争夺同一层级。
PlaybackRun、MediaSession、revision、fencing 等词只属于 API、诊断与实现。

内容区仍以主导航“播放列表”为入口，但页面内明确分为三个平级视图：

```text
播放列表  |  音频资源  |  播放记录
```

“音频资源”因此拥有完整、唯一的管理入口；“添加内容”只打开面向当前 Playlist 的选择器。旧原型
左下角的“音频文件”按钮删除，不再制造两个含义不明的入口。

## 2. 用户任务，而不是数据库功能

| 用户此刻想做什么 | 首选入口 | 最短操作路径 | 完成信号 |
|---|---|---|---|
| 把一个 Playlist 从头放到书房 | 播放列表 | 选择列表 → 全部播放 → 书房音响 → 播放 | 书房出现当前项与进度 |
| 从某一项开始播放后续内容 | Playlist 详情 | 该 item 的播放按钮 → 选择音响 → 播放 | 该 item 成为当前项 |
| 接着上次没听完的位置 | Playlist 详情的“上次位置” | 选择一条候选 → 继续播放 → 选择音响 | 新播放显示来源候选 |
| 创建并整理 Playlist | 播放列表 | 新建 → 编辑模式 → 添加内容 → 重排/设置 → 保存 | 返回只读详情且 revision 更新 |
| 上传一次、以后复用 | 音频资源或添加内容 | 上传 → 校验 → 补充展示信息 → 保存/加入列表 | 资源可被搜索和引用 |
| 把已有资源加入 Playlist | Playlist 编辑 | 添加内容 → 搜索/筛选 → 多选 → 添加 | items 出现在编辑草稿中 |
| 修正资源的展示名称 | 音频资源 | 搜索 → 打开详情 → 编辑名称 → 保存 | 所有未覆盖 item 显示新名称 |
| 修复失效外部链接 | 音频资源 | 筛选“不可用” → 打开详情 → 更新链接 → 验证 | 状态恢复 available |
| 看过去播过什么 | 播放记录 | 筛选时间/Playlist/音响/结果 | 只读列表回答事实，不提供播放动作 |
| 查为什么没播出来 | 活动 | 从失败记录进入关联活动 | 看到协议、输出和脱敏原因 |

同一能力可以有符合上下文的捷径，但必须复用同一个交互。例如音响详情允许“播放内容”，其结果
是打开 Playlist/资源选择器并固定目标音响；它不能另造一套房间 Queue 或第二种播放状态。

## 3. 音频资源是可管理对象

“文件”不能覆盖 external URL，因此产品统一称为“音频资源”。资源不是完整音乐库：没有艺术家、
专辑、封面、歌词或目录扫描，但必须足以被人找回、理解和维护。

### 用户可编辑

| 字段 | 规则 | 为什么需要 |
|---|---|---|
| 展示名称 | 必填；上传后默认取不含路径的原文件名，可随时修改 | 用户不应通过物理文件名识别内容 |
| 说明 | 可选短文本 | 记录版本、用途或内容摘要，不引入专门媒体元数据体系 |
| 标签 | 可选、去重的短标签列表 | 当资源很多时提供跨 Playlist 的轻量分类；不建立目录树 |
| 外部链接 | 仅 external URL 可通过显式“更新链接”修改 | 修复过期或迁移后的定位；与普通改名分开并触发活动冲突检查 |

### 系统维护、只读展示

| 字段 | 来源 |
|---|---|
| 来源类型 | managed file / external URL |
| 原始文件名 | 上传请求，仅作来源说明；永远不作为存储路径 |
| 格式、时长、大小 | 内容探测结果；URL 无法可靠取得时显示未知 |
| 内容哈希 | managed file 去重依据；普通 UI 不展示完整值 |
| 状态 | available / unavailable / deleted |
| 创建与更新时间 | repository |
| 被哪些 Playlist 引用 | playlist_items 派生 |
| 最近播放时间与次数 | media_sessions 派生，不另存统计表 |
| 脱敏来源摘要 | blob 类型或去掉 query/fragment 的 URL 摘要 |

上传后的 blob 不可被“替换文件”；新内容产生新资源，Playlist item 再显式换引用。外部 URL 的
“更新链接”保留逻辑资源身份，但 UI 必须说明它会影响所有引用该资源的 Playlist。正在播放时复用
统一的 keep/reload/stop conflict。

数据层只需在 `media_assets` 增加 `description`、`tags_json`、`original_filename` 和 `updated_at`；
不新增第七张业务表。标签首版是资源的轻量属性，不提供层级、权限、智能集合或自动规则。

评审补充约束：实现保持简单。上述字段直接属于 `media_assets`；不抽象 Metadata/Tag/Collection
领域层，不建立标签关系表，不预建复杂全文索引，首版只做 SQLite 可验证的名称/说明/标签匹配。

## 4. 大量资源时如何找到已有内容

“添加内容”不能直接倾倒一长列已有音频。它是一个选择器，默认只显示 available 资源，并提供：

- 关键词：匹配展示名称、说明、标签和原始文件名；
- 筛选：上传文件 / 外部 URL、可用 / 不可用、已引用 / 未引用、标签；
- 排序：最近使用、最近添加、名称、时长；
- 服务端分页；首版使用稳定 `limit + offset`，不在浏览器加载全部对象；
- 多选与明确的“添加 N 项”，保留当前筛选和选择；
- 固定动作“上传新音频”和“添加外部 URL”，完成后自动选中新资源，但仍由用户提交“添加”。

完整资源管理位于“音频资源”视图，使用同一搜索与筛选模型，并额外提供编辑、查看引用、直接播放
到音响和保守删除。选择器与管理页共享查询 API 和组件，但一个完成“选入当前 Playlist”，另一个
完成“维护资源”，不会再用相同按钮文案制造重复入口。

## 5. Playlist 查看态与编辑态

### 查看态

- 标题、说明、item 数、总时长和默认顺序/循环；
- 主动作“全部播放”；每个 item 提供“从此项播放”；
- 当前在哪些音响播放、当前 item、真实进度和可用控制；
- 最多三条可恢复候选，按最近更新时间排序；候选显示原音响、item、位置和时间；
- 内容不可用时在原位置显示原因，不隐藏、不自动跳过；
- 进入编辑、归档和播放记录的明确入口。

“全部播放”固定从第一项开始，语义不能暗中变成续播。“从此项播放”固定以该 item 为第一项，随后
按本次 order/repeat 执行。续播只能从单独的“上次位置”入口发起。

### 编辑态

编辑不是几个零散弹窗，而是同一详情页的明确模式：

- 标题、说明、默认顺序与循环变为可编辑控件；
- item 行显示拖动手柄、移除、替换资源和 Playlist 内标题；
- PlaylistItem 标题是可选覆盖；为空时始终显示 MediaAsset 的展示名称；
- “添加内容”打开可搜索选择器；
- 页面底部固定“取消 / 保存更改”；离开时有未保存提示；
- 保存携带打开页面时的 revision；冲突时只给“重新载入最新定义”和“放弃本次保存”，不尝试自动合并；
- 修改当前 item 时，提交后才出现一次 keep/reload/stop 决策，取消不发送 mutation；
- 新建 Playlist 直接进入同一编辑态，空列表在保存前不能播放。

## 6. 选择音响与播放方式

Playlist 的“全部播放”“从此项播放”“继续播放”，以及单个音频资源的“播放到音响”，共用同一
选音响对话框。对话框一次只选一台音响，避免让用户误认为多台播放会精确同步。

对话框需要显示：

- 音响名称、online/unknown/offline 和 Receiver Suite readiness；
- 当前是否已有声音以及来源摘要；
- 本次顺序/随机与不循环/列表循环，可覆盖 Playlist 默认值但不回写定义；
- 最终起点摘要，例如“从第一项开始”“从 Coastline 开始”或“从第 3 项 12:18 继续”；
- 目标已有声音时，主要按钮改成“替换并播放”，明确会 preempt；offline 音响不可提交。

提交后立即关闭对话框，并在详情和总览出现 starting 状态。MCP/HTTP 返回 run/session id 后不是
“已经发声”；只有实体 renderer pull 后才显示 playing。失败停在当前项并给一个主要下一步，不自动
重试、跳过或换音响。

## 7. 页面职责重新排序

### 总览

优先回答“现在家里哪里在响、从哪里来、是否正常”。每条声路按来源 → 协议 → 音响排列。Playlist
声路有上一项/下一项；普通投放没有。没有声音时给两个入口：浏览播放列表、查看手机投放方法。
总览不显示续播候选，不编辑内容，不出现 run/session 等实现词。

### 音响

优先回答“这台音响能不能接收声音”。列表显示 online、Receiver Suite、当前声音和启用状态；详情
承担改名、启停和协议健康。“播放内容”是可选上下文捷径，只预选目标音响并复用内容选择流程。

### 播放列表

承载“播放列表 / 音频资源 / 播放记录”三个子视图。首次进入默认回到最近使用的子视图与 Playlist，
但 URL/hash 应能直接定位具体对象。

### 播放记录

只读。字段为开始时间、结束时间/时长、内容摘要、目标音响、结果与原因。可以筛选、查看详情、跳转
到仍存在的 Playlist 或资源详情，但不能直接继续、重播或发起任何播放。跳转对象详情是信息导航，
不是播放动作。

### 活动

保留协议和系统诊断职责。播放记录可链接关联活动，活动也可链接关联 session/run 的只读摘要；两边
不复制完整字段。

## 8. 首版范围与暂不建设

### 必须有

- 音频资源完整管理视图；
- 资源展示名称、说明、标签编辑和外部链接显式更新；
- 搜索、筛选、排序和分页；
- Playlist 查看态、新建/编辑态、item 标题覆盖、添加/替换/移除/重排；
- 全部播放、从 item 播放、资源直接播放、显式续播；
- 统一单音响选择器与 preempt 提示；
- 当前播放、只读播放记录、活动关联；
- 所有空、加载、上传、不可用、离线、冲突和存储错误状态。

### 明确不做

- 文件夹、层级 Collection、智能 Playlist 或自动标签；
- 艺术家、专辑、封面、歌词、推荐和浏览器内试听；
- 批量元数据编辑、批量删除和自动垃圾回收；
- 多选音响同步播放、临时 Queue 编辑和 Play Next；
- 自动恢复、自动跳过、自动重试或备用资源。

## 9. 原型必须证明的关键路径

下一版评审原型不追求把所有视觉细节当成生产稿，但必须可完整走通：

1. 新建 Playlist → 进入编辑态 → 搜索已有资源 → 上传新资源 → 添加 → 重排 → 保存；
2. 编辑资源展示名称、说明和标签，区分原始文件名；
3. Playlist 全部播放与从指定 item 播放，选音响并看到 preempt 提示；
4. 同一 Playlist 的两个独立播放位置与显式续播；
5. 播放记录无播放动作；
6. 资源不可用、音响离线、revision conflict、active-item conflict 和存储错误；
7. 总览与音响页只承担各自任务，不复制编辑器。

视觉生产化（SVG 图标、精确间距、最终动效与完整组件状态）在产品功能获批后单独完成，不能用粗糙
占位符直接进入生产 UI。

# ADR-0010：无媒体库地支持定点起播与会话 Seek

## 状态

Accepted

## 背景

CastFabric 的 Agent 文件播放使用一次性上传事务与进程内临时文件。用户需要两种不同
语义：新媒体从指定秒数开始播放，以及对当前播放会话跳转。把两次调用交给 Agent 编排
会引入时序竞争；为此建设可复用素材 ID、数据库或媒体库又超出产品边界。

## 决策

1. `play_url` 和一次性 `play_file` 上传事务接受可选的非负整数
   `start_position_seconds`。上传完成后，应用服务在同一个调用边界内执行播放与定位。
2. 独立 `seek` 控制接受 `target_id`、非负整数 `position_seconds` 和可选
   `if_session_id`。会话 ID 仅作为防止误控新会话的乐观并发条件，不是素材 ID。
3. 文件仍只用一次性 `upload_id` 和服务端内部媒体 token；停止、替换、超时或进程关闭
   后删除。停止后复播需要重新上传。
4. `PlaybackService` 是 HTTP、MCP、Skill 和未来入口共享的语义边界；Skill 只处理本地
   文件字节、时间换算与客户端播放列表，不自行编排“播放后再 Seek”。
5. 输出端通过 `PlaybackTarget.seek(seconds)` 执行定位。标准 DLNA 适配器映射到
   AVTransport `Seek` 的 `REL_TIME`；不支持的适配器返回失败，公开层返回稳定错误。
6. `start_position_seconds=0` 与省略字段等价，不发送多余 Seek。

## 安全与验收

- 本次开发和发布验收禁止向真实音响发送播放、Seek、暂停、停止或音量命令。
- 单元测试、Fake DMR、模拟输出适配器和只读工具发现是本次唯一允许的验证方式。
- 不把模拟通过记录成真机播放通过；既有真机声音验证保持原记录。

## 后果

- 两个用户语义对外独立，内部复用同一 Seek 原语。
- 不增加数据库、媒体目录、素材列表或长期文件生命周期。
- 初始定点播放在当前 DLNA 输出上由服务端原子编排为 Play 后 Seek；未来可在适配器内
  针对设备能力优化顺序，而不改变 HTTP 或 MCP 契约。
- 当前版本只承诺秒级整数定位。实际精度由输出设备与媒体格式决定。

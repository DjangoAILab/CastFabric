# ADR-0004：每个输出音响拥有独立接收器组

## 状态

Accepted for implementation

## 背景

CastFabric 的输出不是一个全局唯一的“当前音响”。局域网里可能同时存在客厅、卧室、
书房等多个音响，用户希望按音响独立决定是否由 CastFabric 暴露接收入口。

早期原型使用“选择输出目标”“默认音响”的单选表达，容易让人理解为所有协议只能
绑定到同一台音响。这与产品目标不符。

## 决策

- 输出音响是一级实体，可以同时存在多个。
- 每台已启用音响对应一个独立的 **Receiver Suite**。
- 一个 Receiver Suite 默认包含虚拟 DLNA、AirPlay、MiPlay 三种入口；协议能力可以
  因兼容性单独显示为就绪、降级或不可用，但音响启停是最主要的用户控制。
- 启用或停用只影响当前音响，不影响其他音响。
- 不设置全局默认音响，也不提供互斥的“当前输出”选择。
- 同一 Receiver Suite 内的输入会话互斥；不同音响的 Receiver Suite 可以并行工作。
- 对外名称默认使用 `CastFabric · <音响名>`。若发送端需要区分协议，可由协议自身的
  设备类型标识区分，不把协议名堆进主名称。

## 产品呈现

- 首页展示全部音响的健康状态和当前会话，而不是只展示一个目标。
- 音响管理页以音响为单位展示启停、别名、实体 DLNA 状态和三种接收入口状态。
- 活动记录必须包含音响、入口协议、发送源、状态和时间。
- “连接配置”只管理发现、网络、接收入口命名规则和高级扩展，不承担音响单选。

## 后果

- 运行时需要按音响隔离端口、服务实例、会话状态和诊断信息。
- 多音响同时启用时必须解决 AirPlay、MiPlay 与虚拟 DLNA 的实例标识和端口分配。
- 首页和 API 都需要集合模型，不能再返回单个 `selected_target`。
- 旧配置中的默认目标只作为迁移时的首个启用项，不再保留为长期产品概念。
